> **TL;DR.** HAMMER is the first framework to ground 3D affordances directly via MLLMs — no 2D segmenters, no attribute descriptions. It improves aIoU by **+1.69** on the PIAD Seen split and **+5.39** on the Unseen split over the previous best. We additionally release **PIADv1-C**, a new corruption-style benchmark for evaluating robustness in 3D affordance grounding.

### 阶段 2：冻结 PartField 缓存与简单头消融

`-m partfield` 是独立的 PartField backbone 消融：保留单个 `[CONT]`、Qwen/LoRA、
原 LiftTo3D 和 AffordDecoder，使用 PartFieldAdapter 取代 PointBackbone。
adapter 对冻结特征进行可训练投影、局部 kNN 汇聚与簇上下文融合，保持完整 N 点输出，
并生成 `[64,128,512,N]` 四个尺度；它不在训练时加载 PartField 推理模型。
投影、MLP、LayerNorm 和几何汇聚使用 FP32 运算，梯度保留到 DeepSpeed 的 BF16 参数。
该模式与尚未实现的 `crag3d` 明确区分，`-m hammer` 继续运行原版路径。
训练集和评估集中的任一样本缺缓存、坐标不齐或权重版本不一致都会报错。

PartField [官方代码](https://github.com/nv-tlabs/PartField)通过子模块固定在
`373025dbd283bb44cc4a6dc78c99994dbc91de32`。使用[官方 Objaverse checkpoint](https://huggingface.co/mikaelaangel/partfield-ckpt/blob/main/model_objaverse.ckpt)，
SHA256 为 `463efc8a3afd3913142aa025e0125c00f16ef452b8de6a132ebe32bbe7877ee4`；
提取入口检查官方 commit、源文件状态和 checkpoint 哈希。
提取器直接复用官方 `TriPlanePC2Encoder`、`TriplaneTransformer` 和
`sample_triplane_feat`，分别严格加载两个完整特征组件，显式排除未使用的 SDF/辅助头。
每个进程绑定占用检查通过的 GPU UUID，批量处理相同点数的 XYZ，保留查询点索引。

当前主机复用已有 `hammer` 环境的 PyTorch `2.5.0+cu118` 和
`torch_scatter==2.1.2+pt25cu118`，通过独立 `.venv/partfield` 使用这些已安装依赖，
仅在该虚拟环境中补充 `boto3==1.43.126`、`loguru==0.7.3`，不修改 HAMMER 训练环境。
这与官方推荐的 PyTorch 2.4/CUDA 12.4 环境不同，不能视为相同环境的复现。

### 阶段 3：三角色 CRIM 与训练集反事实监督

`-m crim` 使用 PartField + CRIM + 原简单分割头，保留原 CE/CA 主损失和评测指标。
回答由现有类别、任务字段自动拼接，恰好包含 `[CONTACT]`、`[EFFECT]`、`[EXCLUDE]`
各一次；按精确 token ID 和 conversation offset 读取隐藏状态，保留 assistant CE 标签。
CONTACT 对 HOI 图像 token 做注意力读取，EFFECT 对齐功能正负原型，EXCLUDE 监督
当前任务的困难负点和部件，另加温和的角色分离约束。原数据没有人工接触点标注，
这些角色不被解释为手部接触真值；本阶段未启用 SAM3。

CONTACT 使用跨 rank 可导的当前特征和持久化 FIFO 队列（容量 512）做任务对比。
图像身份根据已读取的 RGB 尺寸和像素内容计算，同一图片的跨路径副本不会被当作新正样本。
仅训练特征入队；没有合法正对的启动批次明确记录有效数为 0。预测路径不读取 GT 热力图。
新增损失及有效样本计数接入原日志；trainer 的数据迭代仅捕获 `StopIteration`，
避免掩盖真实数据错误，自动恢复也只接受存在 `latest` 的 checkpoint 目录。

CF 索引只读取所选训练清单及其标签，按实际 XYZ 身份、物体和任务选择首个无歧义代表，
以规范点序对齐标签；排除空 GT、重复坐标标签歧义及 min/max 软 IoU 不低于 0.7 的配对。
训练时以 product 软 IoU 做自身 GT 与另一任务 GT 的 margin ranking。已生成的合法配对数为：

| PIADv1 Unseen | 8,038 |

### 阶段 4：功能关系图与可微能量解码

`-m crag3d` 使用 PartField + 三角色 CRIM + FGED，完整模式中的 FGED 替换旧的
LiftTo3D/AffordDecoder；其他三个模型模式保留各自路径。FunctionalGraph 先用部件原型
和几何特征形成部件表示，再由 EFFECT/EXCLUDE 共同计算功能分数，融合点特征与三角色
得到 `y0`、正证据置信度（下界 0.5）和负证据。GT 只进入随后的损失分支。

稀疏图每点最多包含 16 条局部 kNN 边和 4 条同簇远距离边；N=2048 时每个 shape
最多有 40,960 个边槽，padding 不参与能量或监督。距离查询分块、边 MLP 使用 activation
checkpoint，保持 O(Nk) 边存储，不分配完整 N×N 邻接。正负边分别受 EFFECT/EXCLUDE
条件化，并以冻结 PartField 特征交互为主要判别依据。

能量包含正证据 anchoring、正边平滑、负边排斥和负证据惩罚四项。非负系数用 softplus
参数化，按 Hessian 的 Gershgorin 上界确定安全步长，在 FP32 中执行默认 5 次投影更新。
解析梯度对每条边的两端同时累加，保留 `y0`、边权和角色的梯度链；推理也能在 `no_grad`
下运行。输出保留原四个兼容键，`pred_afford` 为 `y_final`，另提供 `y0`、`part_scores`
和 `energy_history` 供日志或可视化读取。

主 CE/CA 权重仍为 1/2，保留角色和 CF 损失；新增部件、图、`y0` 辅助 CA 损失的默认
权重分别为 1、0.1、0.5。图损失包含正/负边软 BCE 与节点负证据 BCE；高/低响应阈值为
0.6/0.1，负候选要求归一化空间距离不超过 1.5 或冻结 PF cosine 不低于 0.5，
中间响应降低监督权重。训练日志复用原 `evaluate()` 比较各 rank 最后一个微批的
`aIoU(y0)` 与 `aIoU(y_final)`；这是训练诊断，不用于选择 checkpoint，也不改变原评测定义。

### 阶段 5：完整训练与严格断点恢复（首轮与恢复已通过，完整日程进行中）

保留原 `train.py`、DeepSpeed ZeRO-2、LoRA、AdamW、WarmupDecayLR 和
`tools/trainer.py` 的训练/验证调用。PIADv1 默认仍为 30 epochs、每轮 196 次 optimizer
updates、全局 batch 64。当前运行使用 GPU 0–3、每卡 microbatch 2、累积 8、BF16；
LoRA r=16/alpha=32，主 CE/CA 权重仍为 1/2。`--train_workers` 只控制 DeepSpeed
训练 I/O worker 数，默认每 rank 2；`--workers` 仍控制验证 DataLoader，本次设为 2。

两种加载语义明确区分：

- `--initialize_from_hammer /absolute/legacy/checkpoint` 只初始化兼容的完整 VLM
  基座及已有 LoRA，不恢复旧 optimizer、scheduler、epoch 或旧 3D 解码模块。全部 VLM
  键和形状必须匹配；旧 `[CONT]` 行不复制，三个新角色行和 CRAG 模块保留新初始化。
  旧 checkpoint 不记录 LoRA alpha，使用 `--hammer_lora_alpha` 声明源实验的实际值
  （原 HAMMER 为 32），目标普通 LoRA 的 alpha 必须一致，不能由权重猜测。新增目标
  LoRA 保留 A、清零 B，保持迁移时的 VLM 行为。本次完整训练没有启用旧 HAMMER 初始化。
- `--resume_crag /absolute/crag/checkpoint`（与 `--resume` 同义）恢复完整训练状态。
  原生 DS 断点包含 Qwen/LoRA、三个 token 的输入/输出 embedding、CRIM、CONTACT queue、
  PartFieldAdapter、FGED、FP32 master、Adam moments 和 scheduler，并保存各 rank RNG。
  加载前严格校验模型、词表、PartField 版本、数据清单、损失、训练参数与源码 SHA256；
  加载使用 `load_module_strict=True`，且核对训练状态的抽样签名，旧 HAMMER 断点不能作为 CRAG resume。

`exp/<experiment>/last_model` 保存每轮完整结束后的最新断点，`model` 保留原验证 aIoU
选出的最佳断点。所有 rank 完成原生保存、processor 与完成合同落盘后，才原子更新
`latest`；最佳断点通过同一文件系统上的 hard links 引用该轮原生分片，不重复保存一套
多 GB 权重。成功发布新断点后清理该输出目录的上一份最新/最佳 tag，保留仍有 hard link
引用的文件。只支持完整 epoch 边界恢复；重新创建 DataLoader workers，不能声称逐位重放
之前预取的样本流。

原入口仍验证 `split="test"` 并按其 aIoU 选优。这与实施规范中“不以 test 选模型”的要求
有冲突，沿用原协议并在 `provenance.json` 中明确记录；没有改划分、`evaluate()` 的阈值或
