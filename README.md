> **TL;DR.** HAMMER is the first framework to ground 3D affordances directly via MLLMs — no 2D segmenters, no attribute descriptions. It improves aIoU by **+1.69** on the PIAD Seen split and **+5.39** on the Unseen split over the previous best. We additionally release **PIADv1-C**, a new corruption-style benchmark for evaluating robustness in 3D affordance grounding.

### 阶段 2：冻结 PartField 缓存与简单头消融

`-m partfield` 是独立的 PartField backbone 消融：保留单个 `[CONT]`、Qwen/LoRA、
原 LiftTo3D 和 AffordDecoder，使用 PartFieldAdapter 取代 PointBackbone。
adapter 对冻结特征进行可训练投影、局部 kNN 汇聚与簇上下文融合，保持完整 N 点输出，
并生成 `[64,128,512,N]` 四个尺度；它不在训练时加载 PartField 推理模型。
投影、MLP、LayerNorm 和几何汇聚使用 FP32 运算，梯度保留到 DeepSpeed 的 BF16 参数。
该模式与尚未实现的 `crag3d` 明确区分，`-m hammer` 继续运行原版路径。
训练集和评估集中的任一样本缺缓存、坐标不齐或权重版本不一致都会报错。

PartField [官方代码](https://github.com/nv-tlabs/PartField)通过子模块固定在
`373025dbd283bb44cc4a6dc78c99994dbc91de32`。使用[官方 Objaverse checkpoint](https://huggingface.co/mikaelaangel/partfield-ckpt/blob/main/model_objaverse.ckpt)，
SHA256 为 `463efc8a3afd3913142aa025e0125c00f16ef452b8de6a132ebe32bbe7877ee4`；
提取入口检查官方 commit、源文件状态和 checkpoint 哈希。
提取器直接复用官方 `TriPlanePC2Encoder`、`TriplaneTransformer` 和
`sample_triplane_feat`，分别严格加载两个完整特征组件，显式排除未使用的 SDF/辅助头。
每个进程绑定占用检查通过的 GPU UUID，批量处理相同点数的 XYZ，保留查询点索引。

当前主机复用已有 `hammer` 环境的 PyTorch `2.5.0+cu118` 和
`torch_scatter==2.1.2+pt25cu118`，通过独立 `.venv/partfield` 使用这些已安装依赖，
仅在该虚拟环境中补充 `boto3==1.43.126`、`loguru==0.7.3`，不修改 HAMMER 训练环境。
这与官方推荐的 PyTorch 2.4/CUDA 12.4 环境不同，不能视为相同环境的复现。

### 阶段 3：三角色 CRIM 与训练集反事实监督

`-m crim` 使用 PartField + CRIM + 原简单分割头，保留原 CE/CA 主损失和评测指标。
回答由现有类别、任务字段自动拼接，恰好包含 `[CONTACT]`、`[EFFECT]`、`[EXCLUDE]`
各一次；按精确 token ID 和 conversation offset 读取隐藏状态，保留 assistant CE 标签。
CONTACT 对 HOI 图像 token 做注意力读取，EFFECT 对齐功能正负原型，EXCLUDE 监督
当前任务的困难负点和部件，另加温和的角色分离约束。原数据没有人工接触点标注，
这些角色不被解释为手部接触真值；本阶段未启用 SAM3。

CONTACT 使用跨 rank 可导的当前特征和持久化 FIFO 队列（容量 512）做任务对比。
图像身份根据已读取的 RGB 尺寸和像素内容计算，同一图片的跨路径副本不会被当作新正样本。
仅训练特征入队；没有合法正对的启动批次明确记录有效数为 0。预测路径不读取 GT 热力图。
新增损失及有效样本计数接入原日志；trainer 的数据迭代仅捕获 `StopIteration`，
避免掩盖真实数据错误，自动恢复也只接受存在 `latest` 的 checkpoint 目录。

CF 索引只读取所选训练清单及其标签，按实际 XYZ 身份、物体和任务选择首个无歧义代表，
以规范点序对齐标签；排除空 GT、重复坐标标签歧义及 min/max 软 IoU 不低于 0.7 的配对。
训练时以 product 软 IoU 做自身 GT 与另一任务 GT 的 margin ranking。已生成的合法配对数为：

| PIADv1 Unseen | 8,038 |
| PIADv2 Seen | 7,596 |

### 阶段 4：功能关系图与可微能量解码

`-m crag3d` 使用 PartField + 三角色 CRIM + FGED，完整模式中的 FGED 替换旧的

### aIoU 自动优化：实验约定（2026-11-12，测量准备中）

用户授权以前台 Codex Goal 执行可回退实验，目标是相同完整 PIADv1 Seen 测试协议下
`aIoU >= 0.2154`（已测本地 HAMMER 为 `0.2153273158622429`）。
实验分支为 `codex/crag-aiou-autoresearch`，隔离 worktree 位于本地主目录的
`exp/crag_aiou_autoresearch`，不会移动、暂存或提交主目录未跟踪的 `CRAG3D.md`。
控制入口为用户安装的 `codex-autoresearch/scripts/autoresearch.py`；启动后由其 `finish`
统一提交、测量、保留或回退实验，不能手动修改控制历史来恢复或制造结果。

每次测量都从阶段 5 的同一个 `global_step5292` CRAG 最佳原生模型初始化，**只加载模型**，
新建 optimizer/scheduler，epoch 和 global step 从零开始；旧 checkpoint、完成合同和 RNG
保持原样，不把不同源码/日程伪装成严格断点恢复。源词表、PartField、数据清单、LoRA 和
模型形状必须匹配。固定微调 2 epochs × 196 steps，4 GPU（仅物理 0–3）、全局 batch 64、
microbatch 2 × accumulation 8、BF16、seed 3407、LR `1e-5`，原损失权重和 100-step warmup
不变。先以原 CF-only 采样完成相同预算对照，再验证混合采样修复；每次候选均重新从固定
源权重出发，不沿用上个候选的微调结果。

统一评测第 2 轮的 `last_model`，不从中间轮次按 test 分数选优；复用锁定的原指标和
阶段 6 固定逐样本问答抽样，完整 1012 例，输出最终 aIoU 给控制脚本。指标和数据清单
由固定 guard 检查，测量和 guard 不属于可变的实验源码范围。候选范围限于 CRAG 模型/
损失、训练采样和初始化所需代码。目标达成或用户要求停止时结束；没有擅自设定实验轮数
上限。仅训练初始化、隔离分支和测量工具的准备不等于模型已优于 HAMMER。

本次短微调从已见过原训练标签的权重出发；不能把重新划出的训练开发集称为完全未见
验证。原 1012 例 test 已用于历史选模和错误分析，并继续作为用户指定的开发验收指标，
即使突破目标，也不能声称这是无偏的独立泛化结果。本轮不更改测试标签、清单或指标，
不使用测试 GT 训练、不为 Display/Bag/Microwave/Chair 编写类别硬编码预测规则。
